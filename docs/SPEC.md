# MDs manager — технічна документація

2026-11-05 · Дмитро

## Огляд

**MDs manager — власний AI-адміністратор салону M&D: відповідає клієнтам в Instagram Direct і Telegram, записує до майстра, нагадує про візит і кидає все важливе в адмін-чат.** Аналог MyChatBot, але тільки з тим, що потрібно одному салону, без абонплати за платформу — платиш лише за сервер і AI-токени.

**MVP (версія 1):**

- Instagram Direct: AI відповідає на питання про послуги, ціни, адресу, графік.
- Telegram-бот: той самий агент + існуючий запис через бота M&D.
- Запис: агент бачить вільні слоти майстрів з урахуванням тривалості послуги і створює запис.
- Нагадування клієнту за 24 год і за 2 год до візиту.
- Передача людині: скарги, алергії, складне фарбування, «покличте адміністратора» → сповіщення в Telegram-групу адмінів, бот замовкає.
- Адмінка в Telegram: записи на день, скасування, перенесення, ручний запис, пауза бота.

**Не входить у v1 (можна потім):** коментарі під постами, реакції на сторіс, Viber, WhatsApp, голосові дзвінки, онлайн-оплата, веб-CRM, розсилки, аналітика.

**Критерій готовності:** 20 тестових діалогів без помилок у даті/часі, жодного подвійного запису, нагадування приходять вчасно в київському часі.

## Архітектура

Один сервер приймає всі повідомлення, викликає Claude, а Claude через інструменти просить сервер перевірити слоти чи створити запис — сам у базу він не пише.

> _Діаграма: архітектура MDs manager · 6 компонентів (див. оригінал документа)_

**Потік одного повідомлення:**

1. Клієнт пише в Direct → Meta шле вебхук на `/webhook/instagram` → сервер перевіряє підпис і кладе повідомлення в БД.
2. Сервер збирає контекст: останні 20 повідомлень діалогу, картку клієнта, системний промпт з прайсом.
3. Виклик Claude API з інструментами. Якщо Claude просить `find_free_slots` — сервер виконує запит до БД і повертає результат; цикл триває, доки Claude не дасть фінальний текст.
4. Сервер надсилає відповідь у той самий канал і зберігає її в БД.
5. Якщо Claude викликав `handoff_to_human` — діалог позначається `paused`, в адмін-групу летить сповіщення з посиланням, бот більше не відповідає, поки адмін не поверне.

## Стек і хостинг

Python — бо Claude Code пише його найчистіше, а для Telegram і вебхуків є зрілі бібліотеки; усе живе на одному VPS у Docker.

| Шар | Вибір | Чому |
|---|---|---|
| Мова | Python 3.12 | Найпростіше читати й правити самому |
| Веб-сервер | FastAPI + Uvicorn | Вебхуки Meta й Telegram, асинхронність |
| Telegram | aiogram 3 | Клієнтський бот і адмін-команди в одному процесі |
| AI | `anthropic` Python SDK, модель `claude-haiku-5-5` | Tool use з коробки, дешево; `claude-sonnet-5-5` як запасна для складних діалогів |
| БД | SQLite (v1) → PostgreSQL (якщо філії) | SQLite = один файл, бекап копіюванням |
| ORM / міграції | SQLAlchemy 2 + Alembic | Схема під контролем |
| Планувальник | APScheduler | Нагадування, щохвилинна перевірка |
| Час | `zoneinfo`, зона `Europe/Kyiv` | Усе в БД — UTC, клієнту — київський час |
| Тести | pytest | Особливо логіка слотів |
| Деплой | Docker Compose + Caddy (HTTPS автоматично) | Meta вимагає HTTPS для вебхука |
| Хостинг | VPS 1–2 vCPU, 2 GB RAM, ЄС | ~$5–7/міс (Hetzner, DigitalOcean — орієнтовно, перевірте) |
| Домен | піддомен, напр. `bot.<ваш-домен>` | Для HTTPS і вебхуків |

**Секрети в ****`.env`****:** `ANTHROPIC_API_KEY`, `IG_ACCESS_TOKEN`, `IG_APP_SECRET`, `IG_VERIFY_TOKEN`, `TG_BOT_TOKEN`, `TG_ADMIN_CHAT_ID`, `DATABASE_URL`, `TZ=Europe/Kyiv`.

## Канали

Найскладніша частина проєкту — не код, а доступ до Instagram: потрібен професійний акаунт, своя Meta-апка і проходження App Review, щоб бот відповідав реальним клієнтам.

### Instagram Direct

| Параметр | Значення |
|---|---|
| API | Instagram API with Instagram Login, хост `graph.instagram.com`; сторінка Facebook не потрібна (Meta docs) |
| Акаунт | Лише професійний: Business або Creator |
| Дозволи | `instagram_business_basic`, `instagram_business_manage_messages` |
| Вебхук-поля | `messages`, `messaging_postbacks`, `messaging_seen` (мінімум — `messages`) |
| Токен | Логін дає токен на 1 год → обмін на 60-денний; потрібне автооновлення по cron (chat-sdk) |
| Вікно відповіді | 24 год після останнього повідомлення клієнта; поза вікном відправка падає з помилкою |
| Human Agent тег | Відповідь до 7 днів, але тільки живою людиною, окремий App Review; боту заборонено |
| Ехо | Власні повідомлення приходять назад з `is_echo` — ігнорувати, інакше бот говоритиме сам із собою |
| Обов'язкова вимога Meta | Має бути шлях до живої людини — у нас це `handoff_to_human` |

**Наслідки для логіки:**

- Нагадування за 24 год **не можна** слати в Instagram, якщо клієнт не писав останні 24 год. Тому при записі агент просить телефон або пропонує перейти в Telegram — нагадування йдуть туди (або SMS у v2).
- Перевіряти `last_inbound_at` перед кожною відправкою в Instagram.
- Поки апка в режимі розробки, бот бачить лише акаунти з роллю в апці — для тестів додайте свій особистий акаунт тестером. Для реальних клієнтів — App Review (і, ймовірно, верифікація бізнесу в Meta); закладіть на це час, від кількох днів до кількох тижнів.

### Telegram

- Бот через BotFather, вебхук на `/webhook/telegram` (або long polling на старті).
- Обмежень вікна немає: нагадування надсилаються будь-коли, якщо клієнт натиснув /start.
- Існуючий бот запису M&D переноситься в цей самий процес: команди `/start`, `/book`, плюс вільний текст іде до AI-агента.
- Адмін-група — окремий чат, ID в `TG_ADMIN_CHAT_ID`; бот — адміністратор групи.

## AI-агент

Агент — це Claude Haiku 5.5 із системним промптом салону і сімома інструментами; усі дати, ціни й слоти він бере лише з інструментів, ніколи не вигадує.

**Модель:** `claude-haiku-5-5` за замовчуванням — $0.10 / $0.50 за 1 млн вхідних / вихідних токенів для промптів до 100K (ціни Haiku 5.5). Перемикання на `claude-sonnet-5-5` ($2 / $10) — через змінну `AI_MODEL`, якщо Haiku плутається. Тримати контекст далеко нижче 100K (останні 20 повідомлень), бо понад 100K Haiku дорожчає вп'ятеро.

**Системний промпт (структура, файл ****`prompts/system.md`****):**

1. Роль: адміністратор салону M&D, стиль — привітний, коротко, українською (відповідає мовою клієнта).
2. Факти салону: адреса, графік, контакти, правила (запізнення, скасування, передоплата) — підставляються з БД при кожному виклику.
3. Прайс і послуги з тривалістю — з БД.
4. Правила: ніколи не називати час без `find_free_slots`; перед `create_booking` повторити клієнту послугу, майстра, дату, час і отримати «так»; не обіцяти знижок, яких немає в БД.
5. Коли кликати людину: скарга, алергія чи реакція шкіри, медичні питання, складне фарбування «з фото», прохання адміністратора, 2 невдалі спроби зрозуміти клієнта.
6. Поточна дата й час у Києві — підставляються кожного разу (без цього модель плутає «завтра»).

**Інструменти:**

| Інструмент | Параметри | Повертає |
|---|---|---|
| `get_services` | `category?` | Послуги: назва, ціна від/до, тривалість, які майстри роблять |
| `get_masters` | `service_id?` | Майстри й їхні послуги |
| `find_free_slots` | `service_id`, `date_from`, `date_to`, `master_id?` | До 6 найближчих вільних слотів |
| `create_booking` | `service_id`, `master_id`, `start_at`, `client_name`, `client_phone?` | ID запису або помилка «слот зайнятий» |
| `get_client_bookings` | — (клієнт з контексту) | Майбутні записи клієнта |
| `cancel_or_reschedule` | `booking_id`, `new_start_at?` | Статус операції |
| `handoff_to_human` | `reason`, `summary` | Підтвердження; діалог ставиться на паузу |

Приклад опису інструмента для API:

```json
{
  "name": "find_free_slots",
  "description": "Повертає вільні слоти для послуги. Викликай ЗАВЖДИ перед тим, як називати клієнту час.",
  "input_schema": {
    "type": "object",
    "properties": {
      "service_id": {"type": "integer"},
      "date_from": {"type": "string", "description": "YYYY-MM-DD, Київ"},
      "date_to": {"type": "string", "description": "YYYY-MM-DD, Київ"},
      "master_id": {"type": "integer"}
    },
    "required": ["service_id", "date_from", "date_to"]
  }
}
```

**Захисні правила в коді (не в промпті):** `create_booking` повторно перевіряє слот у транзакції; ліміт 8 викликів інструментів на одне повідомлення; таймаут Claude 30 с → клієнту «Секунду, уточню у адміністратора» + handoff.

## Модель даних

Десять таблиць; усі часи зберігаються в UTC (`timestamptz`), перетворення в київський час — лише при показі.

| Таблиця | Ключові поля | Примітки |
|---|---|---|
| `salon_settings` | `key`, `value` | Адреса, телефон, правила, текст «про нас» — редагується з адмінки |
| `masters` | `id`, `name`, `tg_user_id?`, `is_active` | Майстер може отримувати свій розклад у Telegram |
| `services` | `id`, `name`, `category`, `price_from`, `price_to`, `duration_min`, `buffer_min`, `is_active` | `buffer_min` — прибирання між клієнтами |
| `master_services` | `master_id`, `service_id` | Хто що робить |
| `work_schedule` | `master_id`, `weekday`, `start_time`, `end_time` | Звичайний тиждень |
| `schedule_exceptions` | `master_id`, `date`, `start_time?`, `end_time?`, `is_day_off` | Лікарняні, відпустки, зміни графіка |
| `clients` | `id`, `name`, `phone?`, `ig_user_id?`, `tg_user_id?`, `notes`, `created_at` | Один клієнт може мати і IG, і TG |
| `bookings` | `id`, `client_id`, `master_id`, `service_id`, `start_at`, `end_at`, `status`, `source`, `reminded_24h`, `reminded_2h`, `created_by` | `status`: confirmed / completed / cancelled / no_show; `source`: instagram / telegram / admin |
| `conversations` + `messages` | `channel`, `client_id`, `state`, `last_inbound_at`; повідомлення: `role`, `text`, `created_at` | `state`: ai / paused (handoff) / closed |

**Захист від подвійного запису:** у Postgres — exclusion constraint на `(master_id, tstzrange(start_at, end_at))` для статусу confirmed; у SQLite — перевірка перетину в тій самій транзакції з `BEGIN IMMEDIATE`.

## Логіка запису, нагадувань і передачі людині

Слоти рахує код, а не AI: агент лише просить їх через `find_free_slots` і пропонує клієнту готові варіанти.

**Алгоритм ****`find_free_slots`****:**

1. Для кожного майстра, що робить послугу, взяти робочий інтервал дня з `work_schedule` з поправкою на `schedule_exceptions`.
2. Відняти зайняті інтервали: confirmed-записи + їхній `buffer_min`.
3. Нарізати вільний час кроком 15 хв; слот валідний, якщо `duration_min + buffer_min` влазить до наступного запису або кінця зміни.
4. Відкинути слоти раніше ніж «зараз + 1 год» (налаштовується `min_lead_min`).
5. Повернути до 6 слотів, розподілених по днях (не 6 підряд на ранок понеділка).

**Створення запису:** транзакція → повторна перевірка перетину → INSERT → сповіщення в адмін-групу «Новий запис: Олена, стрижка до плечей, пт 14:00, Маргарита» → підтвердження клієнту.

**Нагадування (APScheduler, щохвилини):**

| Коли | Умова | Канал | Текст |
|---|---|---|---|
| За 24 год | `reminded_24h = false` | Telegram; Instagram лише якщо `last_inbound_at` < 24 год тому | «Нагадуємо: завтра о 14:00 стрижка у Маргарити. Чекаємо! Якщо плани змінились — напишіть» |
| За 2 год | `reminded_2h = false` | Те саме | «Через 2 години чекаємо вас у M&D, адреса: …» |
| Не вдалося | Вікно Instagram закрите, Telegram немає | Адмін-група | «Не можу нагадати Олені — подзвоніть: +380…» |

**Передача людині:**

- Тригери: виклик `handoff_to_human` агентом, ключові слова клієнта («адміністратор», «людина», «скарга»), команда адміна `/takeover`.
- Дія: `conversation.state = paused`, повідомлення в адмін-групу з причиною, коротким підсумком діалогу і посиланням на чат.
- Поки `paused` — AI мовчить. Адмін відповідає з телефону в Instagram напряму або через бота: `/reply <id> текст`.
- Повернення AI: `/resume <id>` або автоматично через 12 год тиші (налаштовується).
- Неявка: адмін ставить `/noshow <id>` → статус no_show, у картці клієнта лічильник неявок.

## Адмінка в Telegram

Все керування — командами в адмін-групі; команди приймаються лише від `tg_user_id` зі списку `ADMIN_IDS` (ви з Маргаритою).

| Команда | Що робить |
|---|---|
| `/today`, `/tomorrow`, `/day 2026-11-20` | Розклад на день по майстрах |
| `/book` | Ручний запис покроково (кнопки: послуга → майстер → слот → ім'я, телефон) |
| `/cancel <id>`, `/move <id> <дата> <час>` | Скасувати або перенести; клієнт отримує повідомлення, якщо канал відкритий |
| `/noshow <id>`, `/done <id>` | Позначити неявку або виконаний візит |
| `/dayoff <майстер> <дата>` | Вихідний / лікарняний — бот перестає пропонувати слоти |
| `/takeover <id>`, `/resume <id>`, `/reply <id> <текст>` | Керування діалогом і передачею |
| `/pause_all`, `/resume_all` | Аварійно вимкнути / увімкнути AI на всіх каналах |
| `/price` | Показати й відредагувати прайс (кнопки) |
| `/stats` | За тиждень: діалогів, записів від бота, неявок, витрати на AI у $ |
| `/client <телефон>` | Картка клієнта: візити, неявки, нотатки |

Кожне нове звернення, запис, скасування й handoff — окреме повідомлення в групі з кнопками «Відкрити діалог», «Перехопити».

## Безпека й персональні дані

Ви зберігаєте імена, телефони й переписку клієнтів, тож діє Закон України «Про захист персональних даних» №2297-VI; для особистого салону вистачить базової гігієни нижче (це не юридична консультація).

**Технічно:**

- Перевіряти підпис `X-Hub-Signature-256` кожного вебхука Meta через `IG_APP_SECRET`; запити без валідного підпису — 403.
- Telegram-вебхук з `secret_token`, перевірка заголовка `X-Telegram-Bot-Api-Secret-Token`.
- Секрети тільки в `.env` на сервері, `.env` у `.gitignore`; репозиторій приватний.
- SSH лише за ключем, фаєрвол: відкриті 22, 80, 443.
- Щоденний бекап SQLite у зашифрований архів поза сервером (наприклад, у ваш Google Drive), зберігати 14 днів.
- Логи без телефонів і тексту повідомлень — лише ID.

**Вимоги Meta:**

- Повідомляти клієнту, що відповідає автоматичний помічник (перше повідомлення: «Привіт! Я AI-помічник M&D, можу записати або покликати адміністратора»).
- Завжди давати шлях до живої людини.
- Видаляти повідомлення, коли Meta надсилає відповідний вебхук.

**Дані клієнтів:**

- Збирати мінімум: ім'я, телефон, історія візитів.
- Історію переписки чистити старшу за 12 місяців (cron).
- Команда `/forget <телефон>` — повне видалення клієнта на його прохання.
- У Claude API передавати лише ім'я та потрібний контекст, без телефону.

## Вартість експлуатації

При 300 діалогах на місяць MDs manager коштує близько $12/міс проти $49 у MyChatBot Standard, який покриває лише 75–100 діалогів.

**Припущення на одне повідомлення клієнта:** ~15 000 вхідних токенів (промпт + прайс + інструменти + історія, з урахуванням 2–3 кроків tool use) і ~900 вихідних; діалог ≈ 8 повідомлень клієнта.

```latex
\text{Haiku: } 15000 \times \frac{0.10}{10^6} + 900 \times \frac{0.50}{10^6} \approx 0.002\ \$ \text{ за повідомлення}
```

Покладіть цей документ у репозиторій як `docs/SPEC.md`, а `CLAUDE.md` нижче — у корінь: Claude Code читає його на старті кожної сесії.

- Секрети лише через config.py; ніколи не логувати телефони й тексти.
